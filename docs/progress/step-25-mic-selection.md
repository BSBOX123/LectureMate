# Step 25: 녹음 마이크 선택

- 기간: 2026-09-30
- 커밋: (검토 후 커밋 예정)
- 배경: 사용자 말 — *"맥에서 마이크 설정을 내장 마이크로 돌려도 lecture-mate 에서 녹음 시작하면
  계속 휴대폰 마이크를 켜서 수업시간에 자꾸 알림음이 크게 난다"*

## 원인: macOS 기본 입력과 Chrome 이 쓰는 장치는 별개다

`getUserMedia({ audio: {...} })` 에 `deviceId` 를 주지 않으면 **Chrome 이 자기 기준으로 장치를
고른다.** 시스템 설정을 바꿔도 Chrome 은 따르지 않는다.

그래서 녹음을 누를 때마다 아이폰(연속성 마이크)이 켜졌고, 수업 중에 알림음이 크게 울렸다.
Step 24 의 무음 사고(61분)도 같은 뿌리다 — 아이폰이 멀어지면 스트림이 끊긴다.

## 구현

`deviceId: { exact: ... }` 로 장치를 지정한다. `exact` 를 쓰는 이유는, 그 장치가 없을 때 조용히
다른 것으로 넘어가지 않고 오류를 내기 때문이다 (또 아이폰이 켜지는 것을 막는다).

```
[녹음 시작]  [MacBook Air 마이크 ▾]        ← 녹음 버튼 옆 드롭다운
```

선택 로직은 `lib/audio-devices.ts` 로 분리했다.

1. 지난번에 고른 장치가 아직 있으면 그것 (localStorage 에 기억)
2. 없으면 **내장으로 보이는 장치** — 이름에 `MacBook`·`내장`·`Built-in` 등이 있는 것
3. 그것도 없으면 첫 장치

**2번이 이번 문제의 핵심이다.** 한 번도 고른 적이 없어도 아이폰이 잡히지 않는다.

그 밖에:

- 장치가 바뀌면 목록을 다시 읽는다 (`devicechange`) — 에어팟을 끼우거나 빼는 경우
- 녹음 중에는 드롭다운을 잠근다 (스트림을 다시 열어야 바꿀 수 있다)
- 고른 장치가 사라졌으면 `OverconstrainedError` 를 잡아 "고른 마이크를 찾을 수 없습니다" 로 안내
- **이름을 얻으려고 스트림을 열지 않는다.** 그게 바로 지금 막으려는 동작이다. 권한이 없으면
  "마이크 1" 처럼 순서로 표시하고, 녹음을 한 번 하면 그때부터 진짜 이름이 보인다

## 검증

실제 브라우저로 확인했다.

```
실제 장치 목록:
  ‘BXBOX’ 마이크                        ← 아이폰
  Background Music (Virtual)
  Background Music (UI Sounds) (Virtual)
  MacBook Air 마이크 (Built-in)

기본 선택: 기본값 - MacBook Air 마이크 (Built-in)      ← 아이폰이 아니다
```

가짜 장치를 주입한 Chrome 에서도 3개가 모두 뜨고 전환이 된다 (콘솔 오류 없음).

- `lib/audio-devices.test.ts` 6개: 내장 인식, 기억한 선택 우선, 사라진 장치는 내장으로, 고른 적
  없으면 내장, 내장이 없으면 첫 장치, 목록이 비면 null
- web-client 24개 통과. lint·타입 검사·빌드 통과

## 남은 일

- 서버는 어느 마이크로 녹음했는지 모른다. 나중에 "이 녹음은 아이폰으로 찍혔다" 같은 진단이
  필요해지면 녹음 행에 장치 이름을 남길 수 있다
- 내장 마이크 판별은 이름 휴리스틱이다. 못 찾으면 첫 장치를 쓰므로 틀려도 크게 문제되지 않지만,
  이름이 특이한 환경에서는 사용자가 한 번 골라 줘야 한다
