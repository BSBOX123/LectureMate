# Step 24: 마이크 입력 레벨 표시와 무음 경고

- 기간: 2026-09-29
- 커밋: (검토 후 커밋 예정)
- 배경: **61분짜리 수업이 통째로 무음으로 녹음됐다.**

## 사고

사용자가 "모바일 프로그래밍 녹음본이 똑바로 녹음됐는지 확인해 달라" 고 해서 파일을 열어 봤다.

```
26.wav   117.3 MB, 16000Hz 모노 16bit, 61.1분, 헤더 일치
```

파일은 완벽하게 정상이었다. 그런데 안을 보니:

| 녹음 | 최대 진폭 | 0 이 아닌 샘플 |
|---|---|---|
| 9/28 데이터베이스 | 32,762 | 99.7% |
| 9/28 컴퓨터구조 | 32,763 | 99.0% |
| **9/29 모바일프로그래밍** | **0** | **0.0%** |

**61분 내내 0 만 들어왔다.** 파일 크기·길이·헤더가 전부 정상이라 시스템은 "잘 녹음됐다" 고
판단했고, 화면에도 아무 경고가 없었다.

## 원인

이 맥의 오디오 입력 장치 목록이다.

```
‘BXBOX’ 마이크                ← 아이폰 (연속성 마이크)
Background Music              ← 가상 오디오 장치
Background Music (UI Sounds)
MacBook Air 마이크             ← 내장
```

사용자 말: *"계속 아이폰을 마이크로 쓰니까 끊겨"*. 맥이 아이폰을 연속성 마이크로 잡고 있다가
아이폰이 잠기거나 멀어지면 스트림이 끊긴다. **끊긴 뒤에도 WebSocket 은 살아 있어서 0 으로
채워진 PCM 이 계속 쌓였다.**

가상 오디오 장치(`Background Music`)가 입력으로 잡혀도 같은 일이 생길 수 있다.

## 이건 설계 문제다

**녹음 중에 소리가 들어오는지 전혀 확인하지 않았다.** Step 21 에서 실시간 자막을 뺄 때 화면의
피드백도 같이 사라졌고, 그래서 한 시간을 무음으로 녹음하면서도 알 방법이 없었다.

실시간 자막을 뺀 이유는 **모델을 돌리는 비용**(60초 음성에 40초, 발열)이었다. 그런데
**입력이 살아 있는지 아는 데는 모델이 필요 없다.** 진폭만 계산하면 된다.

## 구현

`lib/audio-level.ts` 로 계산을 분리했다 (순수 함수라 테스트하기 쉽다).

```ts
pcmRms(pcm)            // 16bit PCM 덩어리의 RMS (0~1)
rmsToMeter(rms)        // 막대 길이. dB 로 펼친다 (-60dB ~ 0dB)
shouldWarnSilence(ms)  // 10초 이상 무음이면 경고
```

**dB 로 펼치는 이유:** 사람이 느끼는 음량은 로그에 가깝다. RMS 를 그대로 막대에 쓰면 평소
말소리(RMS 0.06)에서 막대가 6% 밖에 안 움직여 "죽은 것처럼" 보인다.

**무음 기준 10초:** 말하다 쉬는 정도로는 뜨지 않아야 한다.

화면(`AudioRecorder`)에는 녹음 중에만 막대가 뜨고, 무음이 이어지면 빨간색으로 바뀌며 문구가
나온다.

```
●━━━━━━━━━━ 입력                        ← 정상 (초록)
●━━━━━━━━━━ 마이크에서 소리가 들어오지 않습니다 (12초). 입력 장치를 확인하세요.  ← 빨강
```

**CPU 비용은 없다시피 하다.** 이미 브라우저에서 만들고 있는 PCM 을 한 번 훑어 제곱합을 구할
뿐이다. 워클릿 메시지마다 `setState` 하면 렌더가 과해지므로 ref 에 모아 두고 100ms 마다만
화면에 반영한다.

## 검증

- `lib/audio-level.test.ts` 8개: 무음 PCM 이 RMS 0 인지(실제 사고 상황), 실측 수준의 말소리가
  기준을 넘는지, 막대가 0~1 을 벗어나지 않는지, 10초 미만에는 경고하지 않는지
- web-client 18개 통과. lint·타입 검사·빌드 통과

**브라우저에서 실제로 녹음해 보는 검증은 하지 못했다.** 헤드리스 Chrome 이 AudioContext 에서
멈춰 더 파지 않았다. 계산 로직은 단위 테스트로 덮었고, 화면 연결은 사용자가 녹음 버튼을 눌러
말해 보면 10초 안에 확인된다.

## 남은 일

- 서버 쪽에서도 무음을 감지할 수 있다 (PCM 이 전부 0 이면 WebSocket 으로 알림). 브라우저가
  꺼져 있어도 잡히지만, 지금은 브라우저 표시만으로 충분하다고 봤다
- 입력 장치를 화면에서 고를 수 있으면 더 낫다 (`enumerateDevices`). 지금은 Chrome 설정으로 간다
