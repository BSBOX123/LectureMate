# Step 20: 채팅 맥락 이어받기 (후속 질문)

- 기간: 2026-09-25
- 커밋: (검토 후 커밋 예정)
- 배경: Step 19 까지는 매 질문이 독립이었다. 공부 도우미에서 가장 크게 비는 부분이었다.

## 문제

```
학생: 외래 키가 뭐야?
어시: 다른 릴레이션의 주키를 가리키는 속성입니다. (2장 11쪽)
학생: 그거 시험에 나와?
어시: "그거"가 무엇을 가리키는지 알 수 없습니다.
```

두 가지가 동시에 망가진다.

1. **프롬프트에 맥락이 없다** — 모델이 "그거"를 해석할 수 없다
2. **검색이 엉뚱해진다** — "그거 시험에 나와?" 를 임베딩하면 외래 키와 가까운 쪽이 안 나온다

두 번째가 더 치명적이다. 프롬프트에 이전 대화를 넣어 줘도 검색 결과에 관련 자료가 없으면 답할 근거 자체가 없다.

## 구현

### 서버는 대화를 저장하지 않는다

클라이언트가 최근 몇 마디를 매번 함께 보낸다.

```jsonc
POST /api/v1/courses/{courseId}/chat
{ "question": "그거 시험에 나와?",
  "history": [ { "role": "user", "text": "외래 키가 뭐야?" },
               { "role": "assistant", "text": "다른 릴레이션의 주키를 가리키는..." } ] }
```

**이렇게 한 이유:** 세션 테이블을 만들면 대화 저장·만료·정리가 전부 따라온다. 지금 필요한 것은 "직전 몇 마디"뿐이고, 그건 화면이 이미 들고 있다. Spring Boot 가 SSE 를 해석하지 않고 중계하는 기존 설계와도 결이 맞는다.

Spring Boot 는 `history` 를 검증만 하고 FastAPI 로 그대로 넘긴다 (`role` 은 `user|assistant`, 최대 20마디, 각 4000자).

### 검색어에 직전 질문을 붙인다

```python
def retrieval_query(question: str, history: list[ChatTurn]) -> str:
    """"그거 시험에 나와?" 같은 후속 질문은 그 자체로는 검색어가 되지 못한다.
    직전 사용자 질문을 앞에 붙여 맥락을 준다."""
    previous = [turn.text for turn in history if turn.role == "user"]
    return f"{previous[-1]} {question}" if previous else question
```

**LLM 으로 질문을 재작성(query rewriting)하는 방법이 더 정확하다.** 하지만 호출이 한 번 늘어 답변이 그만큼 느려진다. Step 19 에서 사용자가 "적당한 성능에 빠른 답변"을 요청했으므로 추가 호출 없는 이 방식을 골랐다. 실측으로 충분히 동작한다(아래 검증).

### 프롬프트

이전 대화가 **있을 때만** 섹션을 넣는다. 빈 `[이전 대화]` 섹션은 모델을 헷갈리게 한다.

```
[이전 대화]
학생: 외래 키가 뭐야?
어시스턴트: 다른 릴레이션의 주키를 가리키는 속성입니다.

[강의 자료]
...
```

시스템 프롬프트에도 규칙을 추가했다.

```
- [이전 대화]가 있으면 그 흐름을 이어서 답한다. "그거", "방금 그건" 같은 말은 이전 대화에서
  무엇을 가리키는지 찾아 이해한다.
```

### 개수 제한

프롬프트와 검색에 쓰는 것은 **최근 4마디**(`MAX_HISTORY_TURNS`)다. 답변 속도를 유지하기 위해서고, 각 마디는 300자로 자른다. 화면도 4마디만 보내지만 서버가 한 번 더 자른다.

빈 답변(생성 실패한 턴)은 화면에서 걸러 보내지 않는다.

## 검증

같은 자료(2장 관계형 모델 41쪽)에 같은 질문을 맥락 있이/없이 던져 비교했다.

| | 검색된 쪽 | 답변 |
|---|---|---|
| **맥락 O** | `[11, 37, 38, 39, 36]` | "**'그거'는 방금 이야기한 외래키로 이해하고** 답하겠습니다" |
| 맥락 X | `[37, 38, 39, 34, 7]` | "'그거'가 무엇을 가리키는지 **이전 대화가 없어서 알 수 없습니다**" |

**외래 키가 설명된 11쪽이 맥락 있을 때만 검색됐다.** 검색어에 직전 질문을 붙이는 방식이 실제로 동작한다는 증거다. 프롬프트만 고쳤다면 모델이 "그거"는 이해해도 근거 자료를 못 받았을 것이다.

맥락이 있을 때도 모델은 "시험 출제 여부는 자료에 없다"고 정확히 답했다 — 맥락을 준다고 없는 근거를 지어내지는 않았다.

- 테스트: FastAPI 25개(신규 4), Spring Boot 42개(신규 3), web-client 7개 통과. lint·타입 검사 통과

## 트러블슈팅

### 테스트 대역 시그니처

`stream_answer` 에 인자가 하나 늘자 `fake_llm` 대역이 깨졌다.

```
TypeError: fake_stream() takes 3 positional arguments but 4 were given
```

대역도 `history=None` 을 받도록 고치고, 기록하는 튜플을 4개로 늘려 **맥락이 실제로 `stream_answer` 까지 도달하는지** 검증하도록 했다. 처음에는 프롬프트를 테스트에서 직접 만들어 확인했는데, 그러면 "전달되는지"는 확인하지 못한다.

## 남은 일

- 대화가 길어지면 4마디 밖의 맥락은 사라진다 (요약 후 누적 방식은 호출이 늘어난다)
- 화면을 새로 고치면 대화가 사라진다 (서버에 저장하지 않으므로)
- LLM 질문 재작성(query rewriting)은 도입하지 않았다. 검색 품질을 평가할 수단이 생기면 비교해 볼 가치가 있다
