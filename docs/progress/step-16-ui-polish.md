# Step 16: 화면 다듬기 (가드 · 타임라인 · 삭제 · 재시도)

- 기간: 2026-09-20
- 커밋: (검토 후 커밋 예정)
- 순서: 로그인 가드 → 타임라인 데이터 → 강의 삭제 → 분석 재시도

## 1. 로그인 라우트 가드

**문제:** 로그인하지 않아도 `/lectures/...` 화면이 열렸습니다. API만 401을 반환해서 빈 화면이 보였습니다.

**해결:** `app/lectures/layout.tsx` 하나로 `/lectures` 아래 전체를 보호합니다.
- 세션 복구 중에는 "불러오는 중"
- 비로그인이면 `/login?next=<원래 경로>` 로 이동
- 로그인 성공 후 `next` 로 돌아감

`useSearchParams`는 Suspense 경계가 필요해서 로그인 폼을 `<Suspense>` 안으로 감쌌습니다.

## 2. 슬라이드 타임라인 (SPEC §2.1-12 신설)

```
GET /api/v1/lectures/{id}/timeline
→ [{ "pageNumber": 5, "speechDurationMs": 184000, "hasExamHint": true }, ...]
```

- `lecture_transcripts`를 `matched_slide_page`로 묶어 발화 길이를 합산합니다. 매칭되지 않은 세그먼트는 제외합니다.
- `slide_annotations.exam_hints`가 있는 페이지에 `hasExamHint`를 표시합니다.
- 두 쿼리 결과를 서비스에서 합칩니다. 집계는 JPQL `group by`, 힌트 여부는 페이지 번호 목록으로 가져와 `Set`으로 조회합니다.
- 화면에서는 발화 분량이 막대 길이로, 시험 힌트가 ★로 보입니다.

추가한 파일: `LectureTranscriptRepository`(SPEC §4.1에 없던 것), `SlideTimelineItem`.

## 3. 강의 삭제 (SPEC §2.1-13 신설)

```
DELETE /api/v1/lectures/{id} → 204
```

- 파일(PDF·WAV·녹음 임시본)을 지우고 강의 행을 삭제합니다.
- 슬라이드·전사·필기는 **DB의 `ON DELETE CASCADE`**가 함께 지웁니다. 애플리케이션에서 일일이 지우지 않습니다.
- 목록 화면에 삭제 버튼을 두고 `confirm`으로 한 번 확인합니다. 되돌릴 수 없기 때문입니다.

## 4. 분석 재시도 (SPEC §2.1-14 신설)

```
POST /api/v1/lectures/{id}/retry → 202
```

- `status=FAILED` 일 때만 허용합니다(아니면 409).
- **슬라이드가 없으면** PDF 파싱부터 다시, **있으면** 오디오 정밀 분석을 다시 돌립니다. 어디서 실패했는지에 따라 알아서 갈라집니다.
- 화면에서는 FAILED 상태일 때만 "분석 다시 시도" 버튼이 나옵니다.

## 이렇게 한 이유

- **가드를 레이아웃에 둔 이유:** 페이지마다 검사를 넣으면 새 화면을 추가할 때 빠뜨리기 쉽습니다. `/lectures` 아래는 전부 로그인이 필요하므로 레이아웃 한 곳이 맞습니다.
- **타임라인을 별도 API로:** 주석 조회(§2.1-4)는 한 페이지만 주므로, 전체 페이지의 분량을 알려면 45번 호출해야 합니다. 집계는 DB가 한 번에 하는 편이 낫습니다.
- **삭제 시 하위 데이터를 애플리케이션에서 지우지 않음:** 스키마에 이미 `ON DELETE CASCADE`가 있습니다. 양쪽에서 지우면 중복이고, DB 제약이 더 확실합니다.
- **재시도를 상태로 분기:** 사용자가 "파싱 실패인지 분석 실패인지" 구분할 필요가 없어야 합니다.

## 검증 결과

**자동 테스트 (총 88개 통과)**
- Spring Boot 39개: 기존 31개 + `LectureManagementTest` 8개
  - 타임라인 집계(페이지별 합계, 힌트 표시), 매칭 안 된 세그먼트 제외, 타인 접근 404
  - 삭제 후 하위 데이터 0건 + 파일 삭제 확인, 타인 404·비로그인 401
  - 재시도: 슬라이드 없으면 파싱 호출, 있으면 배치 분석 호출, FAILED 아니면 409
- FastAPI 40개, web-client 9개 (변경 없음)

**브라우저 검증** (헤드리스 Chrome)

| 항목 | 결과 |
|---|---|
| 비로그인으로 `/lectures/1` 접근 | `/login?next=%2Flectures%2F1` 로 이동 |
| 로그인 후 목록 접근 | 정상 |
| 타임라인 | 1쪽 막대 58%, 2쪽 100% (발화 분량 비율대로) |
| 삭제 | 확인창 → 목록에서 즉시 사라짐 (1개 → 0개) |
| 재시도 | FAILED 상태에서 버튼 노출 → 클릭 → 슬라이드 2건 재생성, READY 복귀 |

재시도는 슬라이드를 지우고 상태를 FAILED로 바꿔 실패 상황을 만든 뒤 확인했습니다.

검증에 사용한 계정과 파일은 모두 삭제했습니다.
